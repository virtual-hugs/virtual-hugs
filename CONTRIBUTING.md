# 💙 Contributing to Virtual Hugs

Thank you for your interest in contributing to Virtual Hugs!

Virtual Hugs is a collaborative project focused on creating a comforting online space for people who are having difficult days. Through interactive activities, mini games, journaling, positive messages, and other features, we hope to create an experience that helps users feel supported and cared for.

This project welcomes contributors of all experience levels, including complete beginners! Virtual Hugs is not just about creating a website - it is also about learning, collaborating, and building something meaningful together.

---

# 🌱 How to Join

Interested in contributing? Follow these steps:

1. Read through the project information and decide which role interests you.
2. Contact the project lead through Discord or another communication platform.
3. Share:
   - Your GitHub username
   - The role(s) you are interested in
   - Any relevant experience (beginner experience is completely okay!)
   - Any ideas or features you would like to contribute

4. Once you join a team:
   - Check the GitHub Project Board for available tasks
   - Choose an issue that interests you
   - Ask questions whenever you need help
   - Start contributing!

Remember: you do not need to be an expert. Learning is a major part of this project!

---

# 🌿 Choosing a Task

All tasks will be organized through GitHub Issues and the Project Board.

Before starting a task:

1. Find an issue that matches your role or interests.
2. Comment on the issue saying that you would like to work on it.
3. Wait until the issue is assigned to you.
4. Move the issue to the appropriate project status once you begin working.

If you have a new feature idea:
- Create a new GitHub Issue
- Explain your idea
- Describe why it would improve the user experience

Everyone is encouraged to contribute ideas. Your perspective matters!

---

# 🌳 Creating a Branch

To keep the project organized, contributors should create a separate branch for each feature, improvement, or bug fix.

Please do not directly edit the `main` branch.

## Branch Naming

Examples:

```
feature/homepage
feature/journal-page
feature/new-mini-game
design/color-palette
fix/navigation-bug
docs/contributing-guide
```

## Creating a Branch

Clone the repository:

```bash
git clone [repository-link]
```

Move into the project folder:

```bash
cd virtual-hugs
```

Create a new branch:

```bash
git checkout -b feature/your-feature-name
```

Example:

```bash
git checkout -b feature/mood-tracker
```

---

# 💻 Making Changes

After creating your branch:

1. Make your changes.
2. Test your changes whenever possible.
3. Save your work.

Stage your changes:

```bash
git add .
```

Commit your changes:

```bash
git commit -m "Describe your changes"
```

Example:

```bash
git commit -m "Added homepage navigation bar"
```

Push your branch:

```bash
git push origin feature/your-feature-name
```

---

# 🔄 Submitting Changes (Pull Requests)

When you finish your work:

1. Go to the Virtual Hugs GitHub repository.
2. Click **Pull Requests**.
3. Click **New Pull Request**.
4. Select your branch.
5. Submit your pull request.

Your pull request should include:

## What you changed

Example:

Created the homepage layout.

## Features added

Example:

- Added navigation bar
- Added mission statement section
- Improved mobile responsiveness

## Notes

Example:

- Need feedback on animation choices
- Unsure about color accessibility

After submitting:

- A team member will review your changes.
- Feedback may be provided.
- Once approved, your changes will be merged into the project.

Pull requests are not meant to be scary — they are simply a way for everyone to collaborate and improve the project together!

# 💬 Communication Expectations

Communication is an important part of making this project successful.

Please:

✅ Ask questions when you are confused  
✅ Share updates about your progress  
✅ Communicate if you need extra time  
✅ Be respectful and supportive toward other contributors  
✅ Give constructive feedback  
✅ Let the team know if you are unable to continue

Everyone has school, extracurricular activities, and other responsibilities. Virtual Hugs is meant to be a flexible learning experience, not a stressful commitment.

If you need to step away from the project, please communicate with the project lead. You will still receive credit for the contributions you completed.

---

# 🧡 Code & Design Guidelines

When contributing:

- Write clear and understandable code.
- Keep your code organized.
- Add comments when they improve understanding.
- Consider accessibility when designing features.
- Think about how your changes affect the user's experience.
- Be open to feedback and improvements.

For design contributions:

- Consider readability and accessibility.
- Keep the Virtual Hugs style consistent.
- Prioritize creating a welcoming and comforting experience.

# ❓ Frequently Asked Questions

## Do I need experience?

No!

Beginners are completely welcome. The only requirement is a willingness to learn and collaborate.

This project is meant to help contributors gain experience while creating something meaningful.

---

## How much time should I spend?

There are no strict deadlines.

To help the project continue moving forward, we recommend around 1–2 hours per week if possible.

If you need more time, communicate with the team!

---

## Can I switch roles?

Yes!

We encourage contributors to explore different areas and find what interests them most.

You can try:

- Development
- Design
- Testing
- Research
- Writing
- Other areas you are curious about

---

## Can I suggest new features?

Absolutely!

Virtual Hugs can only grow through everyone's creativity and ideas.

If you have a feature idea:

1. Create a GitHub Issue
2. Share it with the team
3. Explain how it could improve the user experience
